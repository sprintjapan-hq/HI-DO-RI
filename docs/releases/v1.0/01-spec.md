# v1.0 仕様 — 確定日時を参加者のカレンダーへ追加

## 問題

開催日が確定したあと、参加者は共有ページで日時を読める。自分のカレンダーへ移す操作はない。主催者向けの Google カレンダー同期はログインと OAuth が前提で、ログインしない参加者には使えない。

## 変更

対象は参加者の共有ページ `/p/:shareId` だけ。

開催日が確定しているとき、確定日時のそばに次の 2 つを出す。

1. 「Googleカレンダーに追加」
   - `https://calendar.google.com/calendar/render?action=TEMPLATE` へのリンク
   - `text` はイベント名
   - `dates` は開始と終了を UTC の `YYYYMMDDTHHMMSSZ`
   - `details` に共有 URL を含める
   - `ctz=Asia/Tokyo`
   - 新しいタブで開く
   - OAuth もログインも使わない
2. 「.icsをダウンロード（iPhone・Outlook）」
   - ブラウザ内で RFC 5545 の `VCALENDAR` / `VEVENT` を作ってダウンロードする
   - `UID` は出欠表ごとに安定
   - `DTSTAMP`、UTC の `DTSTART` / `DTEND`、`SUMMARY`、共有 URL を含む `DESCRIPTION`
   - 改行は CRLF
   - `,` `;` `\` と改行をエスケープする
   - ファイル名は安全な ASCII

確定前はこれらの操作を出さない。

### 確定枠の時刻

既存のデータだけを使う。スキーマは増やさない。

- `start` / `end`（`poll_candidates.start_at` / `end_at`）があるときは、その絶対時刻を使う。
- 終了が無いときは、候補ラベル `YYYY/M/D HH:mm〜HH:mm` を日本時間として読む。年が無いラベルは出欠表の作成年（Asia/Tokyo）を使う。これは主催者カレンダーと同じラベル解釈。
- 開始も終了も保存されておらず、ラベルも時刻を持たないときは、カレンダー操作を出さない。確定の表示と「確定日時をコピー」は従来どおり。
- ラベルが開始時刻だけ（既定の入力例 `9/24(水) 19:00`）のときも、開始として読み、終了は 60 分にする。手入力の候補は開始・終了の保存値を持たないため、この読み方が無いとボタンが出ない（プレビューで発見、11/14）。
- 開始はあるが、保存値にもラベルにも終了が無いときは 60 分。出欠表に所要時間のカラムは無い。
- 終日フラグは無い。`start` が `YYYY-MM-DD` の日付だけ、または終日と明示されたときだけ、Google の終日形式と `.ics` の `VALUE=DATE` を使う。終了日が無い終日は翌日を排他終了にする。現状の API はタイムスタンプなので、通常の確定枠は時刻付き。

## 対象外

- 参加者が Google アカウントでログインし、カレンダーへ直接書き込む方式（OAuth）は後続
- 主催者の Google カレンダー同期、Clerk、DB スキーマ、API 契約は変えない

## 成功条件

1. カレンダーへ追加する操作は、開催日の確定後にだけ出る
2. Google のリンクを開くと、日本時間の確定日時がずれていない
3. `.ics` を iPhone または Outlook に取り込むと、同じ時刻になる
4. 主催者の確定とカレンダー同期の流れに回帰がない
5. `/feature-history` の先頭に v1.0 カードが出る
