# v0.9 短仕様 — アクセス解析の日付絞り

## 要件

運営用 `/admin/analytics` に、`analytics_events.created_at` を使った **JST 暦日の期間絞り**を追加する。未指定時は現行どおり累計。スキーマ変更なし。

## 背景

健司さん依頼（2026-11-05 18:28 JST・dr eggbot経由「頼んでください」）。アンドリューの平日 21:00 便で、**前日分の `utm_content`** を読む用途。既存の自前計測（PR #8）に `created_at` と索引があり、書き込み経路は変えない。

## 版

- **version**: `v0.9`（現行公開は `v0.8` / `main` @ `77943e8`）
- **対象面**: `/admin/analytics`、`GET /api/analytics/stats`、`/feature-history` の v0.9 カードのみ
- **非対象**: 参加者カレンダー追加（保留案件）、新イベント種別、計測書き込み、`/privacy`、公開面、スキーマ変更

## 仕様

### API（`artifacts/api-server/src/routes/analytics-stats.ts`）

1. 既存クエリ `excludeVerify` は維持（既定 `true`＝`utm_campaign=hd-verify` 除外）。
2. 任意クエリを追加する。
   - `start=YYYY-MM-DD` … 開始日（JST 暦日、その日 00:00:00 JST 含む）
   - `end=YYYY-MM-DD` … 終了日（JST 暦日、その日の翌日 00:00:00 JST 未満）
3. 挙動:
   - **どちらも省略**: 現行どおり全期間（累計）。
   - **片方だけ指定**: 指定側だけ境界を適用（`start` のみ＝その日以降、`end` のみ＝その日まで）。
   - **両方指定**: `[start 00:00 JST, end+1日 00:00 JST)`。`start > end` または形式不正・存在しない日は `400`。
4. 日付境界は **Asia/Tokyo**。UTC 日付にしない。サーバ側で JST 区間に変換して `created_at` を比較する。
5. 権限は現行どおり運営者のみ（未ログイン 401／OPERATOR以外 403）。
6. レスポンス形（`eventCounts` / `trackingStartedAt`）は変えない。絞り時も同じグルーピング（event × utm 3変数）。

### UI（`artifacts/hidori/src/pages/admin-analytics.tsx`）

1. 「検証用キャンペーン除外」スイッチの近くに期間指定を置く。
2. 必須 UI:
   - **開始日・終了日**の入力（空＝累計側の境界なし）
   - **「昨日」ボタン**: 押すと開始・終了の両方を、画面表示時点の Asia/Tokyo 暦日の前日にセットして再取得する
3. 既定は開始・終了とも空（累計）。データ0件は現行どおり「データがありません」。権限エラー表示は変えない。

### `/feature-history`

先頭に v0.9 カードを1枚追加（既存カードは変更しない）。趣旨:

- アクセス解析で期間（JST）や「昨日」に絞って見られるようにした
- 未指定時はこれまでどおり累計

## 成功条件

1. 開始・終了とも未指定で開くと、現行と同じ累計の表が出る（`excludeVerify` の挙動も同じ）。
2. オペレータが「昨日」を選ぶと、前日 JST の utm 行だけが表に出る（0件なら空表示で落ちない）。
3. `start`/`end` で任意の JST 暦日区間に絞れる。境界が UTC 日でずれない。
4. DB マイグレーション・新テーブル・新カラムなし。
5. OPERATOR 以外は従来どおり 403（未ログインは 401）。
6. `/feature-history` に v0.9 カードが先頭で出る。
7. 本番確認: 運営ログインで「昨日」を選び、表（または空）が出ること。
