# v0.9 短仕様 — アクセス解析の日付絞り

## 要件

運営用 `/admin/analytics` に、`analytics_events.created_at` を使った **JST 暦日の日付絞り**を追加する。未指定時は現行どおり累計。スキーマ変更なし。

## 背景

健司さん依頼（2026-11-05 18:28 JST・dr eggbot経由「頼んでください」）。アンドリューの平日 21:00 便で、**前日分の `utm_content`** を読む用途。既存の自前計測（PR #8）に `created_at` と索引があり、書き込み経路は変えない。

## 版

- **version**: `v0.9`（現行公開は `v0.8` / `main` @ `77943e8`）
- **対象面**: `/admin/analytics`、`GET /api/analytics/stats`、`/feature-history` の v0.9 カードのみ
- **非対象**: 参加者カレンダー追加（保留案件）、新イベント種別、計測書き込み、`/privacy`、公開面、スキーマ変更

## 仕様

### API（`GET /api/analytics/stats`）

1. 既存クエリ `excludeVerify` は維持（既定 `true`＝`utm_campaign=hd-verify` 除外）。
2. 任意クエリ `date=YYYY-MM-DD` を追加する。
   - **省略**: 現行どおり全期間（累計）。
   - **指定**: `created_at` が **Asia/Tokyo のその暦日** `[date 00:00:00 JST, 翌日 00:00:00 JST)` に入る行だけを集計する。
3. 不正な `date`（形式不正・存在しない日）は `400`。権限は現行どおり運営者のみ（401/403）。
4. レスポンス形（`eventCounts` / `trackingStartedAt`）は変えない。絞り時も同じグルーピング（event × utm 3変数）。

### UI（`/admin/analytics`）

1. 「検証用キャンペーン除外」スイッチの近くに、期間の切り替えを置く。
2. 最低限の選択肢:
   - **すべて（累計）** … `date` なし（既定）
   - **昨日** … JST の「昨日」の暦日を `date` に渡す
3. 「昨日」は画面を開いた時点の Asia/Tokyo 暦日の前日。日付境界は JST（UTC 日付にしない）。
4. データ0件のときは現行どおり「データがありません」。権限エラー表示は変えない。

### `/feature-history`

先頭に v0.9 カードを1枚追加（既存カードは変更しない）。掲載内容は実装確定後に最終化するが、趣旨は次のとおり。

- アクセス解析で「昨日」（JST）に絞って見られるようにした
- 未指定時はこれまでどおり累計

## 成功条件

1. `date` なしで開くと、現行と同じ累計の表が出る（`excludeVerify` の挙動も同じ）。
2. 「昨日」を選ぶと、JST 昨日の行だけが表に出る（0件なら空表示で落ちない）。
3. 境界確認: JST で日付が変わる前後の `created_at` が、正しい暦日側に入る（UTC 日でずれない）。
4. DB マイグレーション・新テーブル・新カラムなし。
5. 運営者以外は従来どおり 401/403。
6. `/feature-history` に v0.9 カードが先頭で出る。
7. 本番確認: 運営ログインで「昨日」を選び、表（または空表示）が出ること。

## 実装メモ（拘束しない）

- サーバ側で JST 区間に変換して `created_at` を比較する（クライアントのローカル TZ に依存しない）。
- `created_at` に既存索引あり。追加索引は必須にしない。
